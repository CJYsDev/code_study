## 주차별 관통 주제

**1주차 — 요청 한 건이 어디를 지나는가**

바깥에서 서버 문 앞까지가 네트워크 계층, 문 안에서 누가 집어드는지가 프로세스와 스레드,
그 안에서 데이터를 안전하게 다루는 것이 트랜잭션, 그 비용을 재는 눈금이 Big-O.

**2주차 — 비싼 것에 덜 가는 법**

네 주제가 같은 원리의 변주다.

| 주제 | 무엇이 비싼가 | 어떻게 줄이는가 |
|---|---|---|
| 컨텍스트 스위칭 | 캐시·TLB 무효화 | 전환 횟수를 줄인다 |
| TCP handshake | 왕복 지연 | 연결을 재사용한다 |
| B-tree 인덱스 | 디스크 읽기 | 한 번에 많이 담는다 |
| 배열 vs 연결리스트 | 메모리 접근 | 붙여둔다 (캐시 지역성) |

**3주차 — 앞의 미완성을 닫고, 판단으로 넘어간다**

가상 메모리가 2주차 월요일의 TLB를 설명하고,
HTTP 버전사가 1주차 화요일의 계층 구조가 실제로 작동하는 사례를 보여주며,
정규화/반정규화에서 처음으로 "정답이 없는 판단"을 다룬다.

## 실습 실행법

저장소 루트에서:

```bash
python lab/week02_fri_concurrency_lab.py
```

표준 라이브러리만 사용. 2~3분 소요.

확인하는 것:

- 프로세스 ID와 스레드 ID (1주차 금요일 과제)
- CPU-bound 작업에 스레드를 늘려도 안 빨라지는 것 (GIL)
- IO-bound 작업에 스레드를 늘리면 빨라지는 것
- 프로세스로 바꾸면 CPU-bound가 빨라지는 것 (GIL 우회)
- 코어 수를 넘어서면 이득이 사라지는 지점 (전환 비용)

리눅스라면 옆 터미널에 `vmstat 1`을 띄워두고 `cs` 열을 함께 관찰.
