## 1. 운영 원칙

### 원칙 1 — 단위는 "1일"이 아니라 "1주제 = 1노트"

하루에 못 끝내면 다음 날 이어서 진행한다.
대신 한 주제는 반드시 노트 하나로 닫는다.

### 원칙 2 — 분량은 티어로 조절한다

같은 주제라도 그날 시간에 맞춰 **어디까지 갈지**만 정한다.
티어는 `concept-explainer` 7섹션 템플릿에 그대로 매핑된다.

| 티어 | 시간 | 채우는 섹션 |
|---|---|---|
| A | 15~20분 | 한 줄 요약 / 없으면 생기는 문제 / 비유 |
| B | 40~60분 | + 동작 원리 / 주니어 함정 |
| C | 여유 있는 날 | + 트레이드오프 / 연결되는 CS 지식 + 코드·명령어로 직접 확인 |

시간이 없는 날은 A만 찍고 넘어간다.
단, 진도표에 A만 체크된 주제는 **미완료**로 보고 주말에 B·C를 채운다.

### 원칙 3 — 주 5일 로테이션, 금요일은 통합

| 요일 | 영역 |
|---|---|
| 월 | 운영체제 |
| 화 | 네트워크 |
| 수 | 데이터베이스 |
| 목 | 자료구조·알고리즘 |
| 금 | 통합 — 그 주 4개 주제를 DICONAI 코드 위에서 하나로 엮기 |

금요일이 이 커리큘럼의 핵심이다.
"개념은 아는데 적용이 안 된다"는 문제를 여기서 직접 때린다.

## 4. 기록 규칙

**노트 제목 형식**

```
프로세스와 스레드 — 무엇이 다른가
B-tree 인덱스 — 왜 B-tree를 쓰는가
```

**노트 본문**
`concept-explainer` 7섹션 템플릿을 그대로 사용한다.
티어 A까지만 했다면 나머지 섹션은 제목만 남기고 비워둔다.

**금요일 통합 결과**
판단이 들어간 결정(worker 수 변경, 인덱스 추가 등)은 ADR 문서로 남긴다.
이는 기존 학습 루프 2단계와 합류한다.
